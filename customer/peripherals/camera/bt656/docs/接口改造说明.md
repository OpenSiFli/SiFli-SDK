# ARK7128 驱动接口改造说明

> 适用范围：`customer/peripherals/camera/bt656` 与 `example/rt_device/bt656`
> 变更日期：2026-11
> 目标板：dpi-hdk-lb57e（SF32LB57x HCPU）

> **阅读提示：当前对外接口是 `bt656.h`（`bt656_init/start/get/release/stop/...`），
> 应用不包含 `ark7128.h`。第 1~9 节记录的是改造的第一版（`ark7128_*` 接口，
> 其中 `ark7128_dcmi.*` 后来已删除），仅作历史对照；现状与上一版的差异见
> 第 10 节。**

## 1. 背景与目标

改造前的对外接口存在三个问题：

1. **公开接口分散在两个头文件**：`ark7128.h` 只有 snapshot 接口，stream 全套在
   `ark7128_dcmi.h` 里，而这个头文件同时混着内部实现（`hw_init`、`buffer`、
   `drain_fifo` 等），应用不知道该包含哪个。
2. **三种采集接口、三套缓冲所有权**：`ark7128_get_frame()` 用内部单缓冲、
   `ark7128_dcmi_stream_wait()` 用内部多缓冲且"下次 wait 自动回收"、
   `ark7128_dcmi_buffer()/buf_at()` 直接暴露裸指针。应用只能拿指针反查下标，
   自己再造一套 `preview_busy`/`preview_latest` 管理"哪块还在用"。
3. **所有权没有跨层传递**：驱动不知道上层是否还在读上一帧，可能在显示线程
   读取时被 DMA 覆盖；AHD 双缓冲时"没有空闲块"的兜底会覆盖刚发布的帧。

本次改造把公开面收敛到 `ark7128.h`，用**显式借用/归还**替代隐式回收，
并让"没有空闲缓冲就丢新帧"成为明确、有计数的行为。

## 2. 变更总览

| 旧接口 | 新接口 | 说明 |
|---|---|---|
| `ark7128_get_frame(&f, tmo)` | `ark7128_start(ARK7128_CAPTURE_SNAPSHOT)`<br>`ark7128_get(&f, tmo)`<br>`ark7128_release(&f)`<br>`ark7128_stop()` | snapshot 生命周期显式化 |
| `ark7128_dcmi_stream_start()` | `ark7128_start(ARK7128_CAPTURE_STREAM)` | 内部完成 reconfigure + dcmi_init + stream_start |
| `ark7128_dcmi_stream_wait(&df, tmo)` | `ark7128_get(&f, tmo)` | 返回值改为统一帧结构 |
| —（隐式回收） | `ark7128_release(&f)` | **新增**：显式归还缓冲 |
| `ark7128_dcmi_stream_stop()` | `ark7128_stop()` | |
| `ark7128_dcmi_init(mode)` / `ark7128_dcmi_hw_init()` | 不再由应用调用 | 由 `ark7128_start()` 内部完成 |
| `struct ark7128_dcmi_frame` | `struct ark7128_frame` | 两种帧结构合并 |
| `ark7128_dcmi_stream_buf_count/at()` | 不再由应用调用 | 应用不再需要知道驱动内部下标 |
| `ark7128_mode_info()` | 同签名，返回 `const` | 返回值只读 |
| `ark7128_dcmi.h` | 驱动内部头 | 应用只包含 `ark7128.h` |

`struct ark7128_frame` 新增一个字段：

```c
void *priv;    /* 借还令牌：应用原样传回 ark7128_release()，不要解释/修改 */
```

其余字段（`data/width/height/stride/field/pixfmt/seq/bytes`）含义不变。

## 3. 新接口

```c
/* 生命周期 */
int  ark7128_init(void);
int  ark7128_deinit(void);
int  ark7128_start(ark7128_capture_t mode);   /* SNAPSHOT / STREAM */
int  ark7128_stop(void);

/* 取帧 / 归还 */
int  ark7128_get(struct ark7128_frame *frame, rt_int32_t timeout_ms);
void ark7128_release(struct ark7128_frame *frame);

/* 其它（不变） */
int  ark7128_set_source(rt_uint8_t source);
ark7128_mode_t ark7128_get_mode(void);
const struct ark7128_mode_info *ark7128_mode_info(ark7128_mode_t mode);
uint16_t ark7128_detectchip(void);
uint8_t  ark7128_signalcheck(void);
int  ark7128_reconfigure(rt_int32_t lock_timeout_ms);

/* 新增：诊断计数（stream 模式） */
void ark7128_stats(rt_uint32_t *captured, rt_uint32_t *dropped,
                   rt_uint32_t *errors);
```

语义：

| 调用 | 行为 |
|---|---|
| `ark7128_start(mode)` | 软复位解码器 → 重下寄存器表 → 等锁定 → 初始化 DCMI →（STREAM）开流。已在采集中直接返回 `RT_EOK` |
| `ark7128_get(f, tmo>0)` | 最多等 `tmo` 毫秒 |
| `ark7128_get(f, tmo<=0)` | STREAM：非阻塞，没有帧返回 `-RT_ETIMEOUT`；SNAPSHOT：使用内部默认超时 |
| `ark7128_release(f)` | 归还缓冲；之后 `f->data` 置 NULL。SNAPSHOT 下为空操作 |

**必须成对调用**：每次成功的 `get` 都要对应一次 `release`。忘记 release 的后果
不是内存泄漏，而是可用缓冲逐块减少，最终所有帧都被丢弃（见第 5 节）。

## 4. 缓冲模型

### 4.1 借用 / 归还

```
DMA 写缓冲 A ──完成──► ready 槽（最多 1 帧）
                          │ ark7128_get()
                          ▼
                   in_use 位图置位，应用持有
                          │ ark7128_release()
                          ▼
                   in_use 清零，DMA 可以再次使用
```

- 一个缓冲从 `get` 到 `release` 之间**不会被 DMA 重新写入**；
- `ready` 槽只保留最新一帧：新的帧完成时如果上一帧还没被取走，旧帧被丢弃
  （计入 `dropped`），这就是"丢旧保新"；
- 没有空闲缓冲时（其余缓冲都被应用持有），**不发布新帧**，刚完成的缓冲继续
  交给 DMA，计入 `dropped`。这样不会出现"已发布的帧被覆盖"。

### 4.2 缓冲数量

| 格式 | stream 缓冲数 | 位置 |
|---|---|---|
| CVBS NTSC / PAL（隔行） | 3 | PSRAM1 |
| AHD 720P（逐行） | 2 | PSRAM2 |

所需数量的经验公式：

```
N = L + 2
L = 从"帧完成"到"显示侧读完"之间还能积压的帧数
2 = DMA 正在写的一块 + 显示正在读的一块
```

- CVBS 三缓冲对应 `L = 1`：UI 慢一帧仍有腾挪空间；
- AHD 只有两块（PSRAM2 放不下第三块 1.84 MB），`L` 必须为 0。UI 一慢就丢帧，
  但不会花屏——这是改造后明确保证的行为。

## 5. UI 取数慢会怎样（不堆积）

结论：**不会堆积，内存占用恒定。**

原因：

1. 驱动只有固定 2/3 块缓冲，没有动态分配、没有队列；
2. `ready` 槽最多 1 帧，"丢旧保新"；
3. 其余缓冲被应用持有时，新帧直接丢弃，不发布；
4. 所有丢弃都计入 `ark7128_stats()` 的 `dropped`。

不同慢法对应的表现：

| 场景 | 结果 |
|---|---|
| UI 偶尔慢一帧 | 丢 1~2 帧，画面继续，延迟恒定 |
| UI 长时间不 `release` | 可用缓冲耗尽后持续丢帧；画面卡在最后一帧，不花屏、不涨内存 |
| UI 恢复 `release` | 立即恢复，无需重启采集 |
| 完全不调用 `get` | `ready` 槽保持 1 帧，其余缓冲被 DMA 循环使用，`dropped` 持续增加 |

如果 `dropped` 长期增长，说明显示侧吞吐低于采集帧率，应降低 UI 刷新频率、
缩小图像控件，或改用硬件合成（EPIC）路径。

## 6. 迁移示例

### 6.1 snapshot

```c
/* 旧 */
struct ark7128_frame f;
ark7128_get_frame(&f, 1000);
render(&f);

/* 新 */
ark7128_start(ARK7128_CAPTURE_SNAPSHOT);
for (i = 0; i < loops; i++) {
    if (ark7128_get(&f, 1000) == RT_EOK)
        render(&f);
    ark7128_release(&f);
}
ark7128_stop();
```

### 6.2 stream

```c
/* 旧：wait 返回裸指针，应用反查下标、自己维护 in-use 位图 */
ark7128_dcmi_stream_start();
while (run) {
    struct ark7128_dcmi_frame df;
    if (ark7128_dcmi_stream_wait(&df, 500) == RT_EOK) {
        slot = lookup(stream_buf_at, df.data);
        busy |= 1 << slot;
        render(df.data, df.size);
        busy &= ~(1 << slot);
    }
}
ark7128_dcmi_stream_stop();

/* 新：借 -> 用 -> 还，不再关心下标 */
ark7128_start(ARK7128_CAPTURE_STREAM);
while (run) {
    struct ark7128_frame f;
    if (ark7128_get(&f, 500) == RT_EOK) {
        render(&f);
        ark7128_release(&f);
    }
}
ark7128_stop();
```

## 7. LVGL 图像控件集成

LVGL v8 直接支持 YUV422 图片格式，SDK 的 LVGL GPU 驱动会把它交给 EPIC 硬件
合成，**不需要 CPU 颜色转换，也不需要例程里的 `show_fb` / LCD attach**：

```c
static lv_img_dsc_t dsc;          /* 必须长期有效，LVGL 只存指针 */

/* 在 LVGL 线程里（lv_timer 回调）执行 */
static void cam_timer_cb(lv_timer_t *t)
{
    struct ark7128_frame f;

    if (ark7128_get(&f, 0) != RT_EOK)   /* 非阻塞 */
        return;

    if (dsc.data != RT_NULL)
        lv_img_cache_invalidate_src(&dsc);   /* 地址不变、内容变了 */

    dsc.header.always_zero = 0;
    dsc.header.cf = LV_IMG_CF_YUV422_PACKED_UYVY;
    dsc.header.w  = f.width;
    dsc.header.h  = f.height;
    dsc.data      = f.data;
    dsc.data_size = (uint32_t)f.stride * f.height;
    lv_img_set_src(cam_img, &dsc);

    /* 上一帧已跨过至少一次刷新（EPIC 完成），可以归还 */
    if (held_valid)
        ark7128_release(&held);
    held = f;
    held_valid = RT_TRUE;
}

lv_timer_create(cam_timer_cb, 16, RT_NULL);
```

要点：

- `lv_img_set_src()` 只是标脏，真正读像素发生在之后的 `lv_task_handler()` 刷新里，
  且 EPIC 是异步 DMA。因此**不能**在 `set_src` 后立刻 release，必须延迟到下一次
  更新时归还上一帧；
- 由于 `get` 是"借出即锁定"，驱动会保证 UI 正在使用的那块缓冲不被覆盖；
- 不要从 `lv_timer` 之外的其他线程直接调用 LVGL API（本 SDK 的 LVGL v8 没有
  全局 `lv_lock()`）。相机线程只调用 `ark7128_get/release`，跨线程更新交给
  `lv_timer`；
- 必须每帧调用 `lv_img_cache_invalidate_src()`，否则同一 `src` 指针会被图片缓存
  命中，显示不更新。

完整示例见 `example/rt_device/bt656/src/bt656_lvgl.c`（在 `project` 目录执行
`sdk.py menuconfig --board=dpi-hdk_lb57eybbn6_n16_qspi`，打开顶层选项
`ARK7128 + LVGL preview demo` 后编译）。注意该文件的当前实现已改用第 10 节的
`bt656_get/release`，本节示例里的 `ark7128_*` 调用只用于说明借用/归还时序。

## 8. 未改动的部分

- `ark7128_cfg.c` 的寄存器表、几何、ESCR/ESUR 全部保持原样；
- `ark7128_i2c.c` 的寄存器下发、锁定检测、软复位时序保持不变；
- DCMI 的复位/启停顺序、FIFO 清理、cache 维护、错误恢复分级保持不变；
- **唯一的行为改动**在 stream 的缓冲仲裁：原来"没有空闲块就覆盖刚发布的帧"，
  现在"没有空闲块就丢弃新帧"（见第 4 节）；
- snapshot 的"数据量判据"和"双 FRAME 边界"两条采集路径保持不变。

## 9. 已知限制

1. **LVGL + AHD 不直接支持**：`lv_img_dsc_t` 没有 stride 字段，而 AHD 缓冲里
   仍带 BT.656 定时码（行距可能不是 `2*width`）。LVGL 示例只接受
   `field == 1 && stride == 2*width` 的 CVBS 帧；AHD 需要驱动侧重排或自定义绘制。
2. **单消费者**：`ready` 槽和唤醒信号量只描述"一帧在途"，只支持一个消费线程；
   多个线程并发调用 `bt656_get()` 会互相抢走唤醒。需要多消费者时请在上层加锁
   或复制帧。
3. **`ark7128_mode_info()` 返回静态结构体**：连续查询不同格式会互相覆盖，
   需要长期保存请自行拷贝。
4. **单实例**：`DCMI_IRQHandler` 符号、DMAC1 通道 1、引脚全部固定，
   同一时刻只能有一个 ARK7128 实例。
5. **AHD 只有 2 块缓冲**：UI 消费慢时丢帧率高于 CVBS，属于内存约束。

## 10. 2026-11 二次改造：拆出通用 BT.656 层

第 1~9 节描述的是"驱动自己直连 DCMI/DMA 寄存器"的版本。本次把采集部分
拆成两层，并改为通过 HAL_DCMI 访问硬件。

### 10.1 分层

```
应用
  │ bt656.h（通用接口，不含芯片名）
bt656.c（HAL_DCMI/HAL_DMA、缓冲池、借还、cache、恢复）
  │ bt656_decoder_ops
ark7128.c（I2C、寄存器表、格式、引脚）
```

- `ark7128_dcmi.c/.h` 删除，采集逻辑上移到 `bt656.c`；
- 应用只包含 `bt656.h`，不再出现 `ark7128_*`；
- 以后新增芯片只需实现 `bt656_decoder_ops` 并注册。

### 10.2 接口对照

| 旧 | 新 |
|---|---|
| `ark7128_init()` | `bt656_init()` |
| `ark7128_start(STREAM)` / `ark7128_start(SNAPSHOT)` | `bt656_start()` |
| `ark7128_stop()` | `bt656_stop()` |
| `ark7128_get(&f, tmo)` | `bt656_get(&f, tmo)` |
| `ark7128_release(&f)` | `bt656_release(&f)` |
| `ark7128_stats()` | `bt656_stats()` |
| `ark7128_signalcheck()` | `bt656_signal_locked()` |
| `ark7128_detectchip()` | `bt656_detect()` |
| `ark7128_get_mode()` / `ark7128_mode_info()` | `bt656_get_format()` |
| `ark7128_set_source()` | `bt656_set_source()` |
| `struct ark7128_frame` | `struct bt656_frame` |

`struct ark7128_frame` 的借还令牌字段 `priv` 在 `struct bt656_frame` 里改名为
`token`，语义不变：应用原样传回 `bt656_release()`。

### 10.3 行为变化

- **只保留连续采集**：快照的"数据量判据"和"双 FRAME 边界"两套实现删除，
  `camera snapshot` 改为"起流取一帧再停流"；启动后的第一帧整帧丢弃（启动时刻
  可能落在场/帧中间，数据不是从边界开始写的）。
- **同步码内置**：SAV/EAV 码组由 `bt656.c` 按 `interlace` 选择，不再放在
  `ark7128_cfg.c`；`ark7128_format` 删除 `escr/esur`。
- **FSM/PACK 计入 errors**：原来只统计 OVR，现在 OVR/FSM/PACK 都计入。
- **DCMI 访问方式**：不再直接读写 `hwp_dcmi/hwp_dmac1/hwp_hpsys_rcc`，
  改为 `HAL_DCMI_Init/Start_DMA/Stop`、`HAL_DMA_*`、`HAL_RCC_*`。

### 10.4 HAL_DCMI 的增量扩展

- `DCMI_InitTypeDef` 追加 `SyncUnmask`、`ExtendedSyncSwap`、`DmaBurstNum`、
  `CaptureMode`、`Interface`、`IrqMask`、`IrqMode`；旧调用者零初始化即可。
- `HAL_DCMI_Start_DMA()` 在 `DCMI_IRQ_MODE_APPLICATION` 下支持重复调用（用来换
  缓冲）：忙时先 Abort，让 DMA 通道回到 READY。旧 `DCMI_IRQ_MODE_HAL` 模式不
  Abort，`HAL_DMA_Start_IT()` 仍返回 `HAL_BUSY`，旧语义不变。
- `HAL_DCMI_IRQHandler()` 增加 `DCMI_IRQ_MODE_APPLICATION` 分支：只清标志
  并调用既有回调，不自动 abort DMA / 关中断；`DCMI_IRQ_MODE_HAL` 分支保持不变。
- 新增 `HAL_DCMI_GetRemainingCount()`。
- `HAL_DCMI_Init/Stop/Suspend/Resume` 的旧语义与旧 IRQ 分支保持不变。

### 10.5 第 9 节的过时条目

- 第 3 条（`ark7128_mode_info()` 返回静态结构体）已不适用；
  `bt656_get_format()` 返回芯片格式表里的常量地址。
- 第 4 条仍然成立：`DCMI_IRQHandler`、DMAC1 通道 1、引脚固定，单实例。
- 第 7 节的示例代码仍写作 `ark7128_get/release`；当前实现见
  `example/rt_device/bt656/src/bt656_lvgl.c`（`bt656_get/release`），时序不变。
