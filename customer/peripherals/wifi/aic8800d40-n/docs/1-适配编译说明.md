**芯片型号说明（单库统一架构）:**

host 驱动库与芯片型号无关：所有型号共用同一个 `libaic8800_driver.a`，型号差异由 platform 侧 `aic_chip_desc_port.c` 数据表在运行时按硬件 chipid 分发。`AIC_CHIP_MODEL` 仅控制 platform 侧编译时选择哪份固件数据。

| AIC_CHIP_MODEL | 兼容芯片 | 说明 |
|---------------|---------|------|
| D80 | AIC8800D40 / AIC8800D80 | 支持 5G |
| D80N | AIC8800D80N | 支持 5G（D80 系列, u02 子分支） |
| D80N_U02C | AIC8800D80N | 支持 5G（D80 系列, u02c 子分支） |
| D80X2 | AIC8800D80X2 | 支持 5G, U05 基线, 2T2R |
| DW | AIC8800DW | |
| DC | AIC8800DC | |
| DC_H | AIC8800DC (sub_id=2) | 仅含 _h_u02 固件，节省 Flash |
| DW_H | AIC8800DW (sub_id=2) | 仅含 _h_u02 固件，节省 Flash |
| DL | AIC8800DL | |
| DL_H | AIC8800DL (sub_id=2) | 仅含 _h_u02 固件，节省 Flash |

> `_H` 后缀型号为子型号 (chip sub_id=2)，固件体积更小，适合 Flash 受限场景。

> `D80N` 分 `D80N`（u02 子分支）与 `D80N_U02C`（u02c 子分支）两个编译型号，仅固件套件不同；默认开启 BT，主 FMAC 复用 D80。host 驱动库与运行时行为完全相同（单库统一，无库族区分）。


## 2. 编译系统说明

驱动采用 **两阶段编译架构**，由两层 Makefile 分别管理：

| Makefile | 职责 | 配置文件 | 产出物 |
|----------|------|----------|--------|
| `host/Makefile` | 编译驱动核心（平台无关，型号无关）+ 生成 release 头文件/库文件 | `host/host_config.mk` | `release/lib/libaic8800_driver.a`（单库）、`release/lib/libaic_mbedtls.a`、`release/lib/include/` |
| 顶层 `Makefile` | 编译 platform 适配层 + release 打包 | `platform_config.mk` + `aic_cfg.mk` | `build/libaic_platform.a`、`release/` 完整发布包 |

> **关键**: `platform_config.mk` 是平台移植的唯一配置入口。CC/AR/CFLAGS_ARCH/EXT_INC_DIRS/SRC_PLATFORM/PLATFORM_DFLAGS 全部在此配置，无需每次 make 传参。

```
┌─────────────────────────────┐        ┌──────────────────────────┐
│  Stage 1: host 编译 + release│        │  Stage 2: platform 编译   │
│  (平台无关)                   │ ──→    │  (平台相关)               │
│                             │ 生成   │                          │
│  host/Makefile              │release/│  顶层 Makefile            │
│  驱动 + WPA + mbedTLS       │        │  引用 release/ 中的库和头文件│
└─────────────────────────────┘        └──────────────────────────┘
```

- **Stage 1**: `host/` 下执行 `make release`，编译驱动库并输出到 `release/` (lib + include)
- **Stage 2**: 顶层目录执行 `make`，编译 platform 层，引用 `release/` 中的库和头文件
- **职责分离**: host/Makefile 负责驱动编译与发布；顶层 Makefile 负责平台适配层编译和 release 打包

> **CFLAGS_ARCH 自动传递**: 顶层 Makefile 的 `host-build` 目标会自动将 `platform_config.mk` 中的 `CFLAGS_ARCH` 和 `DFLAGS` 传递给 host 子构建，确保 host 和 platform 浮点 ABI 一致。只需在 `platform_config.mk` 中配好即可，无需在命令行重复传参。

### 2.1 编译命令

顶层 Makefile 自动检测 `host/` 目录是否存在，决定编译策略：

- **host/ 目录存在** (源码态) → 自动从源码编译 host 驱动（`AIC_BUILD_HOST=1`）
- **host/ 目录不存在** (发布态) → 使用 `release/` 预编译库（`AIC_BUILD_HOST=0`）

可通过 `AIC_BUILD_HOST` 宏强制覆盖自动检测：

```bash
make                        # 默认: host/ 存在时自动从源码编译，否则使用 release 库
make AIC_BUILD_HOST=1       # 强制从 host 源码编译驱动
make AIC_BUILD_HOST=0       # 强制使用 release/ 预编译库
```

**常用命令一览**:

| 命令 | 行为 | 适用场景 |
|------|------|----------|
| `make` | 编译 platform 层（自动检测是否编译 host） | 日常开发 |
| `make AIC_BUILD_HOST=1` | 强制从 host 源码编译 + 编译 platform | 有 host 源码时 |
| `make AIC_BUILD_HOST=0` | 仅编译 platform，使用 release 预编译库 | 第三方集成 |
| `make release` | 编译 host + 打包完整发布包到 release/ | 生成发布包 |
| `make release-clean` | 清理 release/ 目录 | 重新生成发布包 |
| `make clean` | 清理 build/ + host/build_SDIO/（切换总线时另带 `AIC_BUS_TYPE=<总线> clean`） | 完全重新编译 |
| `make info` | 显示当前构建配置 | 排查编译问题 |

**完整编译流程**:

```bash
# Step 1: 编译驱动并生成发布包 (在 host/ 下执行)
cd host
make release

# Step 2: 编译 platform (在顶层目录执行)
cd ..
make
```

**交叉编译**:

```bash
# 推荐方式: 在 platform_config.mk 中配置 CC/AR，直接 make
# 临时方式: 命令行传参
cd host
make release CC=arm-none-eabi-gcc AR=arm-none-eabi-ar

cd ..
make CC=arm-none-eabi-gcc AR=arm-none-eabi-ar
```

**platform 编译选项** (推荐在 `platform_config.mk` 中配置):

```bash
# 指定外部 SDK/系统头文件路径 (lwip, rtos 等平台依赖)
make EXT_INC_DIRS="/path/to/lwip/include /path/to/rtos/include"

# 指定平台特定编译宏
make PLATFORM_DFLAGS="-DPLATFORM_YOUR_BOARD"
```

**host 编译选项**:

```bash
# 使用平台已有的 mbedTLS (不链接内置 libaic_mbedtls.a):
# 在 platform_config.mk 中设置 USE_BUILTIN_MBEDTLS=0,
# 平台自行实现 35 个 aic_mbedtls_* 符号 (直接转发示例:
# platform/crypto/aic_mbedtls_port_example.c)
make release
```

**查看构建信息**:

```bash
make info               # 顶层 (platform 信息: CC/AR/包含路径/库路径/源文件数)
cd host && make info    # host 驱动信息
```

### 2.2 host 编译选项

```bash
cd host

make                            # 默认构建 (仅编译, 不生成 release)
make release                    # 编译并生成发布包
make install-headers DEST=/path # 安装公开头文件到指定目录
make AIC_MBEDTLS_INC_DIR=/path  # 指定 mbedtls 头文件
make AIC_BUILD_MBEDTLS_PORT=0   # 外部提供 TLS port 实现 (crypto 层始终编译)
make CC=arm-none-eabi-gcc       # 交叉编译
make info                       # 显示构建配置
```

### 2.3 编译产物

| 产物 | 路径 | 说明 | 来源 |
|------|------|------|------|
| 驱动核心库 | `release/lib/libaic8800_driver.a` | 驱动 + WPA（单库统一，全型号共用） | host/Makefile |
| mbedTLS 库 | `release/lib/libaic_mbedtls.a` | mbedTLS 加密库 | host/Makefile |
| 平台适配库 | `build/libaic_platform.a` | platform 编译输出 | 顶层 Makefile |
| 公开头文件 | `lib/include/`（自包含，与调试形态一致）+ `include/`（兼容） | 驱动 API 头文件 | host/Makefile |

**三个库文件的关系**:

```
libaic8800_driver.a      ← 驱动核心 (闭源，host 层编译，型号无关单库)
    ├── drv_fhost/       ← Full-hosted 驱动逻辑
    ├── drv_macif/       ← MAC 接口层
    ├── drv_wifi/        ← WiFi 接口
    ├── drv_wlan/        ← WLAN 接口
    ├── wpa_supplicant/  ← WPA 认证
    └── porting/src/     ← 桩实现 (弱符号，被 platform 覆盖)

libaic_mbedtls.a         ← mbedTLS 加密库 (host 层编译)
    └── mbedtls_v3_6_2/  ← TLS/WPA 加密原语

libaic_platform.a        ← 平台适配层 (开源，顶层 Makefile 编译)
    ├── rtos/            ← RTOS 原语适配 (FreeRTOS 等)
    ├── hal/             ← SDIO/GPIO/电源/日志
    ├── netif/           ← lwIP 网络接口
    ├── fmac/            ← 固件加载
    └── wifi/            ← WiFi 应用层
```

> **链接关系**: `libaic8800_driver.a` 通过 extern 声明调用 `aicwf_*` 函数，链接器在最终链接时绑定到 `libaic_platform.a` 中的实现。驱动核心的桩实现使用弱符号，platform 层的实现会自动覆盖。
>
> **单库与型号的关系**: 型号差异（总线协议行为/电源管理/5G 支持等）由 `aic_chip_desc_port.c`（编入 `libaic_platform.a`）数据表承载；驱动启动时由硬件 VID/PID 匹配出 chipid 后查表分发，因此同一 `libaic8800_driver.a` 可服务所有型号。

### 2.4 Release 发布目录

`make release` 存在两层不同逻辑：

| 命令 | 执行位置 | 职责 | 产出物 |
|------|----------|------|--------|
| `cd host && make release` | host/ | 编译驱动核心 + 复制库和头文件 | `release/lib/` + `release/lib/include/`（头单一事实源） |
| `make release` | 顶层 | 调用 host release + 组装自包含包（复制 platform/port/构建脚本/CMakeLists） | `release/` 完整发布包 |

**顶层 `make release` 产出完整目录结构**:

```
release/
├── lib/                       # 预编译库 (由 host/Makefile 生成, 单库统一)
│   ├── libaic8800_driver.a    # 驱动核心库 (含 WPA, 全型号共用)
│   ├── libaic_mbedtls.a        # mbedTLS 加密库
│   └── include/                # 公开头 (lib 自包含形态, 与调试 lib/include 一致)
├── include/                   # 驱动自身公开头文件 (由 host/Makefile 生成)
│   ├── drv_api/inc/           # 驱动对外 API (wifi_api.h, netif_api.h 等)
│   ├── drv_wifi/              # WiFi 管理 API
│   └── utils/inc/             # 工具头文件
├── platform/                  # platform 源码 (由顶层 Makefile 复制)
├── port/inc/                  # 移植接口头文件 (由顶层 Makefile 复制)
├── docs/                      # 文档 (由顶层 Makefile 复制，排除内部 porting 指南)
├── Makefile                   # 构建脚本
├── CMakeLists.txt             # CMake 构建脚本（引用模式/全源码模式，与 Makefile 一致）
├── aic_cfg.mk                 # 功能裁剪开关
└── platform_config.mk         # 平台配置
```

注: 移植抽象层头文件位于顶层 `port/inc/`，release 时由顶层 Makefile 复制到 `release/port/inc/`。

**发布前独立编译验证（diff-verify）**：`make diff-verify AIC_CHIP_MODEL=<型号>` 先检查 release 包结构完整性（lib / lib/include / port/inc / platform / Makefile），再以 `AIC_BUILD_HOST=0`（直接引用 lib、不经过 host）独立编译 platform。diff 打包前必须通过。

**第三方使用**: 第三方拿到 `release/` 目录后，无需 `host/` 源码即可独立编译 platform 层：

```bash
cd release
make AIC_BUILD_HOST=0
```

**清理**: `make release-clean` 清理 `release/` 目录中的所有生成内容。

### 2.5 Windows Git Bash 编译注意事项

在 Windows 环境下使用 Git Bash 编译时需注意以下问题（详细说明见移植框架附录 E）：

| 问题 | 解决方案 |
|------|----------|
| `$(MAKE)` 路径含括号 `(x86)` 导致 bash 语法错误 | 所有 `$(MAKE)` 调用加引号：`"$(MAKE)" -C "$(HOST_PATH)"` |
| Windows python3 是 AppExecution stub，sh 中不可执行 | Windows 用 `py -3` 替代 `python3` |
| make 默认用 cmd.exe 无法执行 Unix 命令 | 设置 SHELL 为 Git Bash sh.exe 完整路径 |
| rsync 在 Windows Git Bash 不可用 | 用 `cp -r` + `rm -rf` 替代 |

> 顶层 Makefile 和 host/Makefile 已内置 Windows 兼容性处理，正常使用 `make` 即可。如遇问题，详见移植框架 `docs/aic8800-porting/SKILL.md` 附录 E。

## 3. 驱动框架与移植步骤

驱动采用 **extern 直接链接** 模式：host 层的 port 头文件声明函数接口，platform 层直接实现这些函数，链接器在最终链接时完成绑定。无需 ops 结构体或注册函数。

### 3.1 驱动架构

```
┌───────────────────────────────────────────────────────────┐
│                    应用层 (平台 SDK)                       │
│              wifi_api.h / netif_api.h                     │
└────────────────────────┬──────────────────────────────────┘
                         │ aic_wifi_*() / aic_net_*()
┌────────────────────────┴──────────────────────────────────┐
│               host/ 驱动核心 (闭源 .a)                     │
```

**extern 直接链接示例**:

```c
// port/inc/rtos_port.h — 声明平台必须实现的函数

// platform/rtos/rtos_freertos.c — 直接实现
void *aicwf_rtos_malloc(uint32_t size) {
    return pvPortMalloc(size);
}

// host 层驱动代码 — 直接调用 (链接器绑定)
void *buf = aicwf_rtos_malloc(256);  // 链接到 platform 实现
```

### 3.2 五层移植模块

| # | 模块 | 头文件 | 参考实现 | 职责 | 实施顺序 |
|---|------|--------|---------|------|----------|
| 1 | RTOS 原语 | `port/inc/rtos_port.h` | `platform/rtos/rtos_freertos.c` | 内存/任务/队列/信号量/互斥/定时器/事件组 | 最先 |
| 2 | HAL/硬件抽象 | `port/inc/plat_port.h` | `platform/hal/plat_port.c` | 电源控制/GPIO/调试输出/日志 | 第二 |
| 3 | 固件数据 | `port/inc/aic_fw_port.h` | `platform/fmac/aic_fw_port.c` | 固件数据指针和大小获取 | 第三 |
| 4 | SDIO 总线 | `port/inc/sdio_port.h` | `platform/hal/sdio_port.c` | SDIO 总线读写/CMD52/CMD53/中断/驱动注册 | 第四 |
| 5 | 网络接口 | `port/inc/netif_port.h` | `platform/netif/netif_port.c` | 网络接口管理/IP配置/TX/RX buffer/DHCP/DNS、TX 零拷贝（custom pbuf） | 第五 |
| 6 | 芯片差异数据表 | `port/inc/aic_chip_desc.h` | `platform/fmac/aic_chip_desc_port.c` | 型号差异数据（单库运行时分发，全型号共用一个驱动库的前提） | 随固件 |

> **实施顺序**: RTOS → HAL → 固件 → SDIO → 网络（依赖顺序）。所有声明的函数必须实现，未实现会导致链接错误（`aic_chip_desc_lookup` 缺失同样会链接失败）。
> 详细移植步骤和各模块说明见 `docs/aic8800-porting/SKILL.md` 第四步。

### 3.3 移植实现步骤

**Step 1: 编译驱动库并生成 release**

```bash
cd host

# 使用目标平台交叉编译器编译并生成发布包
make release CC=arm-none-eabi-gcc AR=arm-none-eabi-ar

# 如果平台已有 mbedTLS: 在 platform_config.mk 设置 USE_BUILTIN_MBEDTLS=0,
# 平台自实现 35 个 aic_mbedtls_* 符号 (见 platform/crypto/aic_mbedtls_port_example.c)
make release CC=arm-none-eabi-gcc AR=arm-none-eabi-ar
```

**Step 2: 实现 RTOS 模块 (必须最先完成)**

参考 `platform/rtos/rtos_freertos.c`，实现 `rtos_port.h` 中声明的所有函数。

```c
// my_platform/rtos_impl.c
#include "rtos_port.h"
#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"

void *aicwf_rtos_malloc(uint32_t size) { return pvPortMalloc(size); }
void  aicwf_rtos_free(void *ptr) { vPortFree(ptr); }
int   aicwf_rtos_msleep(int duration) { vTaskDelay(pdMS_TO_TICKS(duration)); return 0; }
// ... 实现所有 rtos_port.h 中声明的函数 ...
```

**Step 3: 实现 SDIO 模块**

参考 `platform/hal/sdio_port.c`，实现 `sdio_port.h` 中声明的所有函数。

```c
// my_platform/sdio_impl.c
#include "sdio_port.h"

int aicwf_sdio_drv_register(void *probe, void *remove) {
    // 注册 SDIO 驱动 probe/remove 回调
}
void aicwf_sdio_claim_host(void *func) { /* 获取 SDIO 总线互斥 */ }
int  aicwf_sdio_readsb(uint32_t fn, void *dst, unsigned int addr, int cnt) { /* CMD53 读 */ }
// ... 实现所有 sdio_port.h 中声明的函数 ...
```

**Step 4: 实现网络模块**

参考 `platform/netif/netif_port.c`，实现 `netif_port.h` 中声明的所有函数。

```c
// my_platform/net_impl.c
#include "netif_port.h"
#include "lwip/netifapi.h"

int aicwf_net_init(void) { /* 初始化网络子系统 */ }

net_buf_tx_t *aicwf_net_buf_tx_alloc(const uint8_t *payload, uint32_t len) { /* 分配 TX buffer */ }
// ... 实现所有 netif_port.h 中声明的函数 ...
```

**Step 5: 实现 HAL 模块**

参考 `platform/hal/plat_port.c`，实现 `plat_port.h` 中声明的所有函数。

```c
// my_platform/hal_impl.c
#include "plat_port.h"

void aicwf_pwr_wifi_pin_init(void) { /* 初始化 WiFi 电源引脚 */ }
int  aicwf_log_printf(const char *fmt, ...) { /* 串口输出 */ }
bool aicwf_platform_test_module_severity(uint32_t module, uint32_t severity) { /* 日志过滤 */ }
// ... 实现所有 plat_port.h 中声明的函数 ...
```

**Step 6: 实现固件模块**

参考 `platform/fmac/aic_fw_port.c`，提供固件数据。

```c
// my_platform/fw_impl.c
#include "aic_fw_port.h"
#include "fw/fw_data.h"   // 内嵌固件数组头文件

// 固件加载模式由 CONFIG_LOAD_FW 控制:
//   0 = 文件系统读取
//   1 = Flash 地址读取
//   2 = 内嵌 C 数组 (默认)
```

**Step 7: 配置 platform_config.mk**

```makefile
# 工具链
CC  = arm-none-eabi-gcc
AR  = arm-none-eabi-ar

# 外部 SDK 头文件路径
EXT_INC_DIRS = /path/to/sdk/lwip/include /path/to/sdk/freertos/include /path/to/sdk/sdio/include

# 平台特定宏
PLATFORM_DFLAGS = -DPLATFORM_YOUR_BOARD

# 启用平台源文件
SRC_PLATFORM += $(PLATFORM_PATH)/rtos/rtos_freertos.c
SRC_PLATFORM += $(PLATFORM_PATH)/hal/plat_port.c
SRC_PLATFORM += $(PLATFORM_PATH)/hal/sdio_port.c
SRC_PLATFORM += $(PLATFORM_PATH)/netif/netif_port.c
SRC_PLATFORM += $(PLATFORM_PATH)/fmac/aic_fw_port.c
SRC_PLATFORM += $(PLATFORM_PATH)/fmac/aic_chip_desc_port.c
SRC_PLATFORM += $(PLATFORM_PATH)/fmac/userconfig.c
```

```bash

# 集成到平台构建系统 (头单一事实源 = lib/include/)
CFLAGS += -Iport/inc
CFLAGS += -Irelease/lib/include/drv_api/inc
CFLAGS += -Irelease/lib/include/drv_wifi
CFLAGS += -Irelease/lib/include/utils/inc

LDFLAGS += -Lrelease/lib -laic_platform -laic8800_driver -laic_mbedtls
```

### 3.4 关键注意事项

1. **所有声明的函数必须实现**: 驱动内部直接调用 `aicwf_*` 函数，未实现会导致链接错误
2. **RTOS 模块优先**: 其他模块内部使用 RTOS 原语 (malloc/task/mutex)，必须先完成 RTOS 适配
3. **固件数据**: 需将对应芯片型号的固件 bin 文件链接到程序中或从 Flash 读取；仅 `CONFIG_LOAD_FW=2`（innermode，默认）时编译内嵌固件数组头文件，file/flash 模式不再包含固件数组
4. **类型定义**: host 层类型通过 `#ifndef` guard 自动处理冲突；platform 层如有冲突可在 `platform_config.mk` 中启用 `SYS_SOCK_DEFINE` / `SYS_NET_DEFINE`
5. **mbedTLS**: crypto 层如平台已有 mbedTLS，设置 `USE_BUILTIN_MBEDTLS=0`（自实现 35 个 `aic_mbedtls_*` 符号，参考 `platform/crypto/aic_mbedtls_port_example.c`；TLS port 层用 `AIC_BUILD_MBEDTLS_PORT=0`，两者独立）
6. **头文件边界**: platform 层严禁 `#include` host 内部头（`layer_common/inc`、`drv_macif`、`drv_fhost` 等），只允许引用 `lib/include/` 公开头 + `port/inc/` 移植接口 + SDK 头；新增/修改 platform 代码后需通过 `make diff-verify` 核对
7. **lwip 配置**: TX 零拷贝与吞吐参数按根目录 `lwipopts.md` 配置（`PBUF_LINK_ENCAPSULATION_HLEN`、`LWIP_TCPIP_CORE_LOCKING` 等）

#### 头文件依赖关系

```
port/inc/                    ← 移植接口 (A)
    ├── aic_porting_types.h  ← 所有类型的基础
    ├── rtos_port.h          ← 依赖: aic_porting_types.h
    ├── sdio_port.h          ← 依赖: rtos_port.h, aic_sdio_types.h
    └── netif_port.h         ← 依赖: aic_netbuf.h

release/lib/include/         ← 驱动 API (B)（单一事实源）
    ├── sdio_def.h           ← 依赖: sdio_port.h (→ A)
    ├── wifi_def.h           ← 依赖: aic_porting_types.h (→ A)
    └── netif_def.h          ← 独立类型定义

外部 SDK                     ← 平台依赖 (C)
    ├── FreeRTOS.h           ← 被 rtos_freertos.c 引用
    ├── lwip/netif.h         ← 被 netif_port.c 引用
    └── sdio.h               ← 被 platform/hal/sdio_port.c 引用
```

> **排错提示**: 如果编译报 `xxx.h: No such file or directory`，先确认对应头文件属于 A/B/C 哪一类，然后检查对应的 include 路径是否已配置。A/B 类路径由 Makefile 自动配置，通常无需手动添加；C 类路径必须在 `platform_config.mk` 的 `EXT_INC_DIRS` 中显式配置。
