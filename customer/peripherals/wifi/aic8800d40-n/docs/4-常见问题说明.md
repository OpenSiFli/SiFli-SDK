#### 1. 如何给wifi芯片上电

在平台层sdio.c文件中，客户适配时需要先根据自己的项目上硬件设计的IO进行配置

```c
static void sdio_main_init(void * argv)
{
    OS_STATUS   status;

    SD_CTRL_BASE_ADDR = 0xD4280800;

	CPUartLogPrintf("sdio init,SDIO:Base 0x%x",SD_CTRL_BASE_ADDR);

#ifdef	ENABLE_SDIO_ADMA
	sdioadmatl = (sdio_desc_table *)sdioadmatblnocache;
#endif

#if defined(ENABLE_SDIO_ADMA) && !defined(SDIO_CLOCK_ADJ)
	set_ddr_sdh_axi_qos();
#endif

    //config wifi and sdio pinmux
    wlan_ldo_en_pin = GPIO_PIN_48;       // change to yourself gpio on project
    wlan_hw_reset_pin = GPIO_PIN_125;    // change to yourself gpio on project
    host_wake_wlan_pin = GPIO_PIN_38;    // change to yourself gpio on project
    wlan_wake_host_pin = GPIO_PIN_31;    // change to yourself gpio on project
    sdio_config_nzc_mifi_dkb_pin(wlan_ldo_en_pin, wlan_hw_reset_pin, host_wake_wlan_pin, wlan_wake_host_pin);
    ...
}

// 配置wlan_ldo_en_pin, wlan_hw_reset_pin, host_wake_wlan_pin, wlan_wake_host_pin
//wlan_ldo_en_pin    使能wifi芯片供电LDO
//wlan_hw_reset_pin  使能wifi芯片pwrkey
//host_wake_wlan_pin 主控唤醒wifi的io
//wlan_wake_host_pin wifi唤醒主控的io

// 其中 wlan_ldo_en_pin，wlan_hw_reset_pin 这两个IO还会响应到 sdio_pdn_wifi，sdio_reset_wifi，
// 这两个接口分别是给wifi芯片掉电，给wifi芯片掉电+重新上电，可以起到异常恢复的作用
```



#### 2. 如何配置DW芯片的供电模式

依据硬件电路设计，区分 LDO/DCDC 两种模式，针对DW芯片，软件需要针对实际使用的供电模式进行响应的配置，配置在 platform/hal/plat_port.c 中

```c
/* define 1: DCDC mode, define 0: LDO mode */
enum {
    VRF_LDO_MODE,
    VRF_DCDC_MODE,
};

/* driver param setting */
int aicwifi_vrf_mode = VRF_DCDC_MODE;
```



#### 3. AIC8800 芯片如何进行自适应测试

芯片正常启动后，通过在主控端下发指令进行切换进入自适应模式，下发指令 **iwpriv shut 3**（前缀可按平台定制），指令下发后，芯片会重新上电，相应的驱动会重新加载，之后通过catlog可以查看到，主控在加载驱动过程中有以下打印，说明顺利进入自适应模式

```c
aicwf_patch_config_8800dc for adaptivity test     //DW/DC
rwnx_patch_config_8800d80 for adaptivity test     //D80
```



#### 4. 如何进行sdio相位调整

##### AIC8800DW 

sdio时钟配置104M，则必须设置相位；由于DW是sdio2.0，不支持tuning，必须动手做实验确认最理想的相位，实验方案是针对同一批版本，取多个样本板子，确认每块板子的理想相位，最终对这些理想相位取平均

修改相位的方法：

```sh
#sdio.c 文件中修改宏
#define SDIO_PHASE 0

#通过sdio_rx_cfg写入相位
#sdio_phase取值范围 0~255
static int sdio_wifi_card_scan(void)
{
	......

    #if SDIO_PHASE
    int sdio_phase = 225;
    #endif
	......
	if(is_sdioclk_48M)
		sdio_enable_clock(base_addr, 0);
	else
	{
        if(sdio_clk_100 == 0)
        {
			......
        }
        else
        {
            #if !defined(AICWIFI_D80)

            #if SDIO_PHASE // adjust sdio host phase
            //set sdr50 mode, support 100M clock
            sdio_set_sdr50();
            sdio_enable_clock(base_addr, 1);
            CPUartLogPrintf("host sdio phase: %d\n", sdio_phase);
            //rx cfg, delay code from 0 to 255
            sdio_rx_cfg(base_addr, sdio_phase);
            #else
			......
            #endif /* SDIO_PHASE */
    ......
}
```

实验方法：

A. 针对同一批板子， 以25步进做标记，并且找到相位好坏的边界，在边界处可以适当缩小步进，例如好的两段相位是a. 0-25，b. 130-255

```  sh
# Y 相位好
# N 相位差
0   25  50  75  100  125  130  140  150  175  200  225  250  255
Y   Y   N   N    N    N   Y/N   Y    Y    Y    Y    Y    Y    Y
```

B. 取大段b；舍弃左端临界部分，130+25=155；计算中间值，(155+255) / 2 = 205

C. 同一批板子取六七块做同样的实验，得到这个几块板子的各自的相位值，最后针对这些相位值取平均

D. 一个配置相位好坏的标准是sdio初始化之后，正常通信过程是否出现 sdio err

##### AIC8800D40/D80

D40/D80芯片支持sdio3.0，支持tuning相位，不需要手动做实验确认相位

#### 7. 开启 BT 后编译报 nimble_stack_start 未定义

`nimble_stack_start()` 由 `STACK/nimble` 协议栈提供，仅当 `AIC_FEATURE_NIMBLE=1`（Make 路径）或 `-DAIC_FEATURE_NIMBLE=ON`（CMake 路径）时才编入。platform 侧调用已用 `#if defined(AIC_FEATURE_BT) && defined(AIC_FEATURE_NIMBLE)` 双重门控，正常情况下只开 `AIC_FEATURE_BT` 不会引用该符号。

若在 SDK 集成中需要 NimBLE：

- Make 路径：`make AIC_FEATURE_BT=1 AIC_FEATURE_NIMBLE=1`（顶层 `all` 会连带编协议栈，也可单独 `make nimble`），产出 `STACK/nimble/build_<总线>/libnimble.a`；
- CMake 路径：`-DAIC_FEATURE_BT=ON -DAIC_FEATURE_NIMBLE=ON`；
- `libnimble.a` 必须**独立链接**（与 wpa `src/ap/utils.c` 同名符号冲突，不入 `libaic8800_driver.a`），放在引用方目标文件之后；
- release/diff 包默认不带 `STACK/nimble`（规避约 59 万行上游代码），需要 BLE 上层栈时按 `make dist AIC_FEATURE_BT=1 AIC_FEATURE_NIMBLE=1` 重新出包，包内该目录可独立编译。

反过来，若平台不需要 BLE 上层栈、只要 BT controller 通道，保持 `AIC_FEATURE_NIMBLE=0` 即可（不会缺符号）；确实要自行提供该符号时，链接顺序须保证其实现可被解析。

#### 8. 切换 BT 开关（AIC_HOST_BT_DRIVER / AIC_HCI_TRANSPORT）后行为异常

host 库采用增量归档（`ar rcs`），切换 `AIC_HOST_BT_DRIVER=0`（裁剪 BT）或更改 `AIC_HCI_TRANSPORT` 后，旧的 BT 相关 `.o` 不会自动从 `libaic8800_driver.a` 中剔除。必须执行 `make clean` 后重新编译，否则库内残留旧对象导致符号冲突或行为不符预期。

#### 9. 双 VIF 并发（APSTA / APP2P）注意事项

- **启动顺序**：`APP2P` 必须先启 P2P 再启 AP（host+app 双层强制，顺序颠倒返回 -12）；`APSTA` 为先 STA 后 AP。
- **vif 索引**：并发时 SoftAP 不在 vif0（STA/P2P 已占 vif0，AP 落到 vif2，vif1 保留给扫描）。ACL 黑白名单、关联表遍历、信道切换均按 `softap_vif_idx` 下发；平台/应用调用带 `fhost_vif_idx` 参数的接口前，请用 `aic_wifi_get_ap_vif_idx()` 取真实索引，不要硬编码 0。
- **STA 上限**：AP 可关联 STA 数由 16 提升至 32，依赖固件 BCMC sta 编号基数确为 32；若某型号固件实际为 16，需在编译期用 `#ifndef` 覆盖相关宏，否则广播帧会被固件静默丢弃。
- **host 常量红线**：`NX_VIRT_DEV_MAX` 需 ≥ 3（vif0=STA/P2P、vif1=扫描、vif2=SoftAP）；`NX_REMOTE_STA_MAX` 必须与固件 BCMC 基数一致（默认 32）。弱内存平台裁剪这两个常量等于放弃并发能力，详见 `platform_config.mk` 内存裁剪说明与 `docs/aic8800-porting/SKILL.md` 4.8.2。
- **平台配套**：每个 vif 一个 netif（`platform/netif/netif_port.c` 的 `PLAT_NETIF_POOL_SIZE` 默认 4，需 ≥ 并发 vif 数）；AP 侧 DHCP Server 需平台 `lwipopts.h` 开 `LWIP_DHCPS`（SoftAP 与 P2P GO 共用）。
